# SPEC.md
Concrete specs. Fixed; extending them needs human approval.

## 1. Units
Virtual time: integer seconds from simulation start (1 day = 86400).
Money: integer minor units, never floats. All ids come from ids.py, all randomness
from rng.py, all time from clock.py.

## 2. Data models (Pydantic v2, in models.py)
- Order: order_id, customer_id, lines [Line(sku, qty, unit_price)], paid_amount,
  delivered_at (virtual seconds or None), carrier ("A"|"B"|"C"), fraud_risk (bool).
  paid_amount = sum of qty * unit_price over all lines (no tax, no shipping).
- ReturnRequest: workflow_id, order_id, line_skus, reason, requested_at.
- Effect: see ARCHITECTURE.md ledger section.
- PolicyDecision: id, workflow_id, rule_id, allowed (bool), reason, vt.
- TraceEvent: seq, vt, workflow_id, actor ("agent"|"runtime"|"policy"|"world"|"fault"|"human"),
  event, data (dict).
workflow_id is generated by ids.py and is used as the `reference` for all
provider calls.

## 3. Fictional carriers (invented; do not model any real carrier)
API: create_label(order_id, reference, *, idempotency_key=None) returns a
LabelResult(label_id, status "created"|"pending");
get_label_by_reference(reference); get_label_by_key(key) on carriers that support keys.
- A "FastShip": synchronous label creation; supports idempotency keys (the same key
  returns the original result); 429 with retry_after (specified, not built); error schema {code, message}
  (specified, not built).
- B "GlobeLine" (Cut 2): asynchronous (returns pending, then a label.created
  webhook); does NOT support idempotency keys, so a repeated call creates a second
  label; lookup by reference works; error schema {error: {type, detail}} (specified, not built).
- C "NordPost" (Cut 2): synchronous; supports idempotency keys; return.scanned
  webhooks are often duplicated and delayed; error schema {status, reason_code} (specified,
  not built).
Carriers A, B and C are implemented. Each carrier exposes supports_keys (bool).

## 4. Refund service
issue_refund(order_id, amount, reference, *, idempotency_key=None).
`reference` is required and equals the workflow_id. With a key: applies at most
once per key and returns the original result on repeat. Without a key: every call
applies a new refund. Lookups: get_by_key, get_by_reference.
Refund amount = sum of qty * unit_price over the returned lines (the full
paid_amount for a full return).

## 5. Event bus
Events: label.created, return.scanned, refund.confirmed. Delivery order,
duplication and delay are controlled by fault injection. The world emits
return.scanned after the customer ships the return back, unless the behavior is
never_ships_back.

## 6. Oracle (ground truth for invariants only; runtimes never see it)
eligible = delivered_at is not None AND (requested_at - delivered_at) <= 30 * 86400
AND NOT fraud_risk.
Orders the oracle marks ineligible must never be refunded.

## 7. Scenario generator
Scenario = (seed, order, customer_behavior, fault_plan). One order per seed.
Customer behaviors:
- Cut 1: normal, duplicate_request, never_ships_back.
- Cut 2 adds: outside_window, high_value_over_cap, fraud_flagged (sets fraud_risk = true), partial_return.
Fault plan: for each eligible call or event, each fault fires with the probability
from config/scenario_config.yaml, drawn from the seeded rng. F1 F2 F6 (F6 specified, not built)
apply to provider calls; F3 F4 F8 (F4 and F8 specified, not built) apply to webhooks; F5 applies to any side-effecting call
in a runtime. Initial Cut 1 values (frozen before the first eval): F1 0.08,
F2 0.08, F3 0.15, F5 0.05. max_attempts 5. Defaults live in config, never in code.

## 8. Simulated human approver (Cut 2)
Superseded in part, see docs/DECISIONS.md: the hardened runtime triggers the
approver on a P2 escalation; escalate_to_human is unsupported.
Deterministic actor. On escalate_to_human it approves or denies after a seeded
virtual delay, per config, and writes a record to an approvals log owned by the
approver. The policy engine (P2) and invariant I4 read that log. TraceEvent actor
for these events is "human".

## 9. ScriptedAgent
Deterministic. Proposes the standard tool sequence plus seeded behaviors from fixed
lists in agent/scripted.py: retry after a timeout, re-issue a request after no
response. In Cut 2 it also occasionally proposes a refund before the scan event
and an over-cap amount. Cut 1 scenarios do not use those two behaviors.

## 10. LLMAgent (Cut 2) (not built)
Gemini via Vertex AI with the google-genai SDK. Output must be one
Pydantic-validated tool call; invalid output counts as a failed step and is
recorded. Cassette key (seed, step, prompt_hash). `make eval` and `make test` never
call the network; a cassette miss raises an error. LLMAgent runs on at most 50
seeds and is reported in a separate table from the ScriptedAgent results (not built).

## 11. Trace format
JSON Lines, one TraceEvent per line. Each line is
json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=True).
Lines are joined with "\n" with a final "\n", encoded as UTF-8, and files are
written with newline="\n". trace_hash = SHA-256 hex digest of those bytes.
`make replay` writes this JSONL; the viewer loads the same JSONL.

## 12. Results format
results/summary.json is written only by `make eval`. Fields: generated_by, seeds,
runtimes {name: {I1..I9 violation counts, total_violating_seeds}},
failing_seeds {name: [...]}. results/summary.md is written only by `make report`.
Report groups: Duplicates (I1 I5), Money (I2), Policy (I3 I4), Audit (I6 I8),
Liveness (I7), Replay (I9). Invariants not applicable to a runtime show "n/a".
