# Crashproof

[![CI](https://github.com/ManojDevarajulu/CrashProof/actions/workflows/ci.yml/badge.svg)](https://github.com/ManojDevarajulu/CrashProof/actions/workflows/ci.yml)

Under injected faults, a naive returns agent breaks a safety invariant on 747 of 1,000 simulated seeds. Adding idempotency keys brings that to 631. The hardened runtime: 0. Every failure replays exactly from its seed.

Crashproof is a deterministic simulation harness that tests whether the runtime around an agent keeps money-moving actions (return labels, refunds) safe when the systems around it fail. The headline results use a scripted agent; a separate 3-seed smoke test used a recorded language model (see below). Everything is a simulation; see Limitations.

### One failure, end to end (seed 1)

Seed 1 is a normal return on carrier C. After the refund is issued, the response is lost (fault F2, a timeout after the effect is applied) and the agent retries.

- **naive:** seq 16 `refund.issued` rfd-000001, seq 18 `fault.F2`, seq 21 `refund.issued` rfd-000002. Two refunds of 8842 against an order that paid 8842 (I1 and I2).
- **hardened:** the same fault at seq 30. The effect is marked unknown (seq 31, `executor.unknown`), the runtime asks the refund service by key and finds it applied (seq 35, `reconcile.applied`). One refund.

Reproduce it:

```
make replay SEED=1 RUNTIME=naive
make replay SEED=1 RUNTIME=hardened
```

Then load results/replay/seed-1-naive.jsonl and seed-1-hardened.jsonl in viewer/index.html. The hardened replay's SHA-256 is 32571347ac4fa35e59a9960eaeb97e3f05ce59bbf7184fe1f1eb4bdbe012595a. Steps are in docs/DEMO.md.

Links: [design notes](docs/DESIGN.md) ([formatted](docs/design.html)), [trace viewer](viewer/index.html), [invariants](docs/INVARIANTS.md), [architecture](docs/ARCHITECTURE.md).

A seed fixes one simulated order, return, customer behaviour and fault schedule. Three runtimes face the same agent, seeds and faults:

- **naive** runs what the agent proposes.
- **keyed** is naive plus idempotency keys.
- **hardened** adds a ledger, reconciliation, a policy engine with human escalation and a scan timeout.

Nine invariants are checked on every run (full definitions in docs/INVARIANTS.md):

| | Invariant |
| --- | --- |
| I1, I5 | At most one refund and at most one return label per return |
| I2 | Total refunded is at most the amount paid |
| I3 | Refund only after the return scan, and only for an eligible order |
| I4 | Refund above the cap only with human approval |
| I6, I8 | Every confirmed effect has a policy decision; refunds and ledger entries match one to one (hardened only) |
| I7 | No workflow still open 72 virtual hours after activity stops |
| I9 | The same seed gives the same trace hash |

## What this shows

- Hardened shows zero violations of nine safety invariants across the 1,000 measured seeds; naive and keyed do not.
- Every measured seed replays to an identical trace hash, so any failure can be reproduced from its seed.
- Idempotency keys fix duplicate refunds but not duplicate labels on a provider that ignores keys, policy or liveness failures.
- Deliberately broken versions of hardened are caught by the invariants, so the zeros are not vacuous.

### Why idempotency keys are not enough

- **Carrier B ignores keys:** Keyed issues duplicate labels on 112 seeds (I5); hardened looks up by reference before retrying.
- **Keys ignore policy:** Keyed refunds before return scans in 286 seeds (I3) and exceeds the refund cap without approval in 176 seeds (I4).
- **Keys ignore liveness:** Keyed leaves 160 workflows open forever without scan timeouts (I7).

### Do the checks catch bugs?

A zero is worth something only if the invariants can fail. Each change below was applied to the hardened runtime on a throwaway branch and run on 300 seeds. The counts are recorded in docs/DECISIONS.md; the patches are not in this repository.

| Change to hardened | Seeds violating |
| --- | --- |
| Refund key removed | I1 19, I2 19, I8 189 |
| Key changes on every attempt | I1 19, I2 19, I5 15, I8 189 |
| Refund cap not enforced | I4 46 |
| Fraud check disabled | I3 32 |
| Scan timeout removed | I7 34 |
| End-of-run reconcile skipped | none (the eval never needed it) |

## Quick start

Required: Python 3.12 and make.

```
make setup
make test
make eval SEEDS=1000 RUNTIMES=naive,keyed,hardened
make report
make replay SEED=1 RUNTIME=naive
```

This reproduces the table above; SEEDS=200 is a faster smoke run. Some tests skip until an eval has produced results/summary.json.

To refresh the results block above after an eval, run `make readme`.

To inspect a replay, open viewer/index.html in a browser and choose the file results/replay/seed-1-naive.jsonl. The viewer shows the SHA-256 of the file, which equals the hash printed by make replay. If your browser shows "SHA-256 unavailable" for a local file, serve the folder with python -m http.server and open localhost port 8000 in your browser, then go to the viewer folder.

## How it works

- A single-threaded discrete-event scheduler drives virtual time; there is no real clock, thread or network.
- Faults are seeded, and each fault decision depends only on the seed and the logical attempt, so every runtime faces the same fault for the same attempt.
- Each seed is one workflow: one order, one return.
- The world (store, three fictional carriers, refund service, event bus) survives simulated crashes; runtime objects are rebuilt, hardened from its ledger.
- The invariants read world records, the trace order, the approvals log and the ledger; I7 for naive and keyed reads the runtime's own terminal flag.
- Details: docs/ARCHITECTURE.md and docs/INVARIANTS.md.

### Built on

- Runtime and concurrency: Python 3.12, stdlib sqlite3 (in-memory ledger), single-threaded discrete-event scheduler.
- Core and config: pydantic v2, PyYAML.
- Quality and invariants: pytest, ruff, mypy.
- LLM evaluation: google-genai (used only for offline cassette recording; evals and tests are 100% offline).

### How it was built

- **Spec first:** architecture, state machine and invariants were defined in docs/ before any code (task T0 in `LOG.md`).
- **Controlled agent pair-programming:** built task by task under the `AGENTS.md` protocol, with human diff review at every step.
- **Enforced determinism:** `tests/test_no_nondeterminism.py` scans the AST to ban system clocks, real sleep, threads and unseeded randomness in `src/`.
- **Honest metrics:** all statistics are measured by `make eval`; a stale README fails the tests.
- **Sabotage testing:** deliberately broken versions of the hardened mechanisms confirm that the invariants fail when they should.

## Limitations

- This is a simulation only. The carriers are fictional and their failure modes encode the author's assumptions. The results say nothing about real carriers or payment systems.
- The 1,000-seed results use a deterministic scripted agent and measure no model. The 3-seed LLM run is a smoke test of one model.
- Faults F4, F6, F7 and F8 (out-of-order delivery, rate limits, provider error schemas, long delays) were specified but not implemented. A refund provider without idempotency keys was not modelled.
- Fault probabilities and the scenario mix were fixed before the final evaluation and are arbitrary. The 1,000 seeds are one sample with no confidence interval.
- Naive and keyed lack a policy engine and scan timeout by design, so their I3, I4 and I7 failures follow from that. Their I7 is a self-report, because they have no ledger.
- Hardened's liveness depends on the scan timeout, and its end-of-run reconcile never changed an outcome. P1 and P5 never deny in the measured seeds.
- This is not a new idea; see the related-work section in docs/DESIGN.md.

More detail, including crash-point coverage and the P3 numbers, is in the "What this does not show" section of docs/DESIGN.md.
